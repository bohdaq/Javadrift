= Enabling snippet and property checks

JD008 and JD009 are off by default. Enable them for documentation whose examples
and configuration declarations you can supply. Start with warning severity, review
the findings and then use error severity for strict enforcement.

[source,yaml]
----
docs:
  include: ['docs/**/*.md', 'docs/**/*.adoc']
checks:
  JD008: warning
  JD009: warning
snippets:
  imports: ['demo.ReportService', 'com.fasterxml.jackson.databind.ObjectMapper']
  release: '17'
----

The snippet imports above belong to the runnable
link:../examples/optional-checks/README.adoc[optional checks sample]. Replace them
with imports for your project. Use docs.include to narrow the scan to guides with
complete examples and known settings. Each Java block is isolated: declarations in
one block are not available in another. Statements and class members are wrapped for
compilation; packaged compilation units must declare their own imports.

== Build the snippet classpath

Use a JDK with javac and compile project classes first. Javadrift discovers main
class outputs under target/classes and build/classes/java/main automatically.
For custom outputs, pass --class-dir. Supply the complete dependency classpath as
a single --classpath argument; entries use the native platform separator, colon
on Linux/macOS and semicolon on Windows.

Build the sample's classes and dependency list from the Javadrift checkout:

[source,shell]
----
mvn -B -DskipTests -pl javadrift-cli -am package
mvn -B -f examples/optional-checks/pom.xml compile dependency:build-classpath -Dmdep.outputFile=target/dependency-classpath.txt
----

On Linux/macOS:

[source,shell]
----
JAVADRIFT_SAMPLE_CP="$(cat examples/optional-checks/target/dependency-classpath.txt)"
java -jar javadrift-cli/target/javadrift.jar check --root examples/optional-checks --classpath "$JAVADRIFT_SAMPLE_CP"
----

On Windows PowerShell:

[source,powershell]
----
$javadriftSampleClasspath = (Get-Content -Raw examples/optional-checks/target/dependency-classpath.txt).Trim()
java -jar javadrift-cli/target/javadrift.jar check --root examples/optional-checks --classpath "$javadriftSampleClasspath"
----

The sample needs Jackson databind, core and annotations. Missing dependencies cause
compilation findings, including when those libraries happen to be bundled inside
Javadrift itself. An explicit nonexistent classpath entry is an input error.
Javadrift compiles snippets without executing them, disables annotation processing
and keeps generated bytecode in memory. Skip deliberately partial Java blocks with
a line containing // javadrift:skip, ... or // ... .

== Declare and scope properties

JD009 reads production .properties and YAML files under src/main/resources,
including nested YAML mappings and multiple YAML documents. It also reads property
names from source Spring configuration metadata and literal System.getProperty
calls or Spring Value annotations in production Java. Test-resource keys are outside
that index. The sample demonstrates the first four declaration forms.

The check recognizes dotted inline keys and dotted key assignments in doc code
blocks. A YAML block using nested mappings is not expanded into dotted documented
keys. Source-only configuration beans without metadata, dynamically constructed
keys and settings owned by other libraries need explicit declarations or reviewed
exceptions. The sample narrowly ignores vendor.trace; adapt that list to the
settings your application actually owns.

Unknown keys produce JD009. Unreadable or malformed declaration files produce an
input error when JD009 is enabled; disabling JD009 leaves property parsing off.

== Review findings and failure behavior

Warning severity reports findings but does not fail the default error threshold.
Set failOn: warning to fail on warnings too, or make selected checks errors.
--warn-only keeps the findings and returns zero for them. Missing classpath files,
invalid configuration and malformed enabled resources still exit 2. A stale strict
scan exits 1; a valid scan exits 0.

The reviewed stale sample has one JD008 return-type mismatch and two JD009 keys:
a spelling error and a setting declared only in tests. The exact findings and
fixture hashes are in validation/optional-checks-triage.json. The walkthrough checks
that all known errors remain and no extra findings appear, using temporary copies:

[source,shell]
----
python scripts/smoke-optional-checks.py --output validation-results/optional-checks.json
----

Use python3 where Python is installed under that name. --skip-build reuses the CLI
JAR; the independent Maven sample is still built. The script saves summary JSON,
individual reports and command logs. It checks enabled, default/disabled, strict,
warning, warn-only, individual-check and restored cases, plus missing classpaths
and malformed property resources. Compiled class files must remain unchanged.

This validates an authored application with pinned real dependencies and reviewed
errors. It does not establish a false-positive rate for optional checks across the
upstream source-only corpus.

The build workflow runs all 22 scenarios on Linux, macOS and Windows with JDK 17
and 21. Each job builds the current CLI, compiles a fresh sample, copies dependency
JARs into paths with spaces, and checks native classpath separators and exact
reviewed locations. Summary JSON, individual reports and command logs are saved
in an optional-checks artifact named for the runner and JDK, including on failure.

== Maven and Gradle integration

The adapters supply compiled main classes and compile dependencies to JD008.
Keep checks and snippet imports in javadrift.yml; no manual dependency classpath
is needed. Use a JDK with javac and configure application compilation normally.
The runnable sample supports both adapters directly from a source checkout:

[source,shell]
----
mvn -B -DskipTests -pl javadrift-maven-plugin -am install
mvn -B -f examples/optional-checks/pom.xml -Pjavadrift verify
./gradlew -p examples/optional-checks check --no-daemon
----

The Maven profile binds the check to verify and writes target/javadrift.json.
The Gradle sample includes the source plugin and analysis engine, and writes JSON
to build/reports/javadrift/report.txt. Use gradlew.bat on Windows.
For Maven findings without build failure, add -Djavadrift.warnOnly=true.
For this Gradle sample, add -PwarnOnly=true; its build maps that property to
javadrift.warnOnly. Warning severity and failOn thresholds apply to both adapters.
Malformed enabled resources still fail builds in warn-only mode. Build adapters
report build failure rather than the CLI's separate input-error exit code.

[source,shell]
----
python scripts/smoke-optional-plugins.py --output validation-results/optional-plugins.json
----

The walkthrough installs the Maven adapter locally and uses the Gradle included
build. --skip-build skips Maven installation. Both temporary consumers use paths
with spaces and validate exact reviewed findings, strict/warn-only behavior,
disabled checks, warnings and their failure threshold, restored guides and input
errors. Gradle additionally verifies unchanged runs are UP-TO-DATE and that guide,
configuration and production resource changes execute the check again. Reports
and command logs are saved alongside the summary, including after failure.
The build workflow runs these 26 adapter scenarios on Ubuntu with JDK 17 and 21;
the Java 17 sample compilation toolchain is installed for both runtime versions.
