source files or chat. The instructions below support future renewal.

== Maven Central

. Sign in at https://central.sonatype.com[Central Portal] with your bohdaq GitHub
  account. Check View Namespaces and confirm io.github.bohdaq is Verified.
  GitHub login often provisions this namespace automatically; otherwise follow
  https://central.sonatype.org/register/namespace/[namespace verification].
. Follow https://central.sonatype.org/publish/generate-portal-token/[Generate a
  Portal Token]. The generated token has a username and password, separate from
  your account login. Store them as CENTRAL_USERNAME and CENTRAL_PASSWORD.
. Install GnuPG if needed (on macOS: brew install gnupg). Generate a publishing
  signing key with gpg --full-generate-key; choose RSA with at least 3072 bits,
  your identity/email, an expiry you can maintain and a passphrase. Existing
  suitable signing keys also work.
. Run gpg --list-secret-keys --keyid-format LONG and copy the full fingerprint.
  Publish the public key and export the private key with the commands below.
  Add the entire armored private-key file as GPG_PRIVATE_KEY and its passphrase
  as GPG_PASSPHRASE. Delete the exported private-key file after adding the secret.

Replace YOUR_FINGERPRINT with your key's full fingerprint:

[source,shell]
----
gpg --keyserver hkps://keyserver.ubuntu.com --send-keys YOUR_FINGERPRINT
gpg --armor --export-secret-keys YOUR_FINGERPRINT > "$TMPDIR/javadrift-signing-key.asc"
----

The build creates sources/Javadoc jars, signs artifacts using the passphrase
from the environment, uploads via Central Portal and waits for publication.
The Gradle adapter depends on javadrift-core from Central, so Central publishing
must finish before the Portal upload.

== Gradle Plugin Portal

. Create or sign in to your account at https://plugins.gradle.org[Gradle Plugin
  Portal]. Open your profile's API Keys tab and generate a publishing API key.
. Save its key and secret as GRADLE_PUBLISH_KEY and GRADLE_PUBLISH_SECRET.
  These are Portal credentials; a GitHub token cannot replace them.

The first plugin publication can require Portal review. See
https://docs.gradle.org/current/userguide/publishing_gradle_plugins.html[Gradle's
publishing guide] for account setup and the approval process.

== Add the six repository secrets

Open https://github.com/bohdaq/Javadrift/settings/secrets/actions[Settings >
Secrets and variables > Actions], then choose New repository secret for each:

[cols="1,2",options="header"]
|===
|Name |Value
|CENTRAL_USERNAME |Central publishing token username
|CENTRAL_PASSWORD |Central publishing token password
|GPG_PRIVATE_KEY |Entire armored private signing key
|GPG_PASSPHRASE |Signing key passphrase
|GRADLE_PUBLISH_KEY |Plugin Portal API key
|GRADLE_PUBLISH_SECRET |Plugin Portal API secret
|===

After all six exist, open https://github.com/bohdaq/Javadrift/actions/workflows/publish-registries.yml[Actions > publish registries].
Choose Run workflow on main and enter the release tag v0.4.0. The selected tag
must exist, contain the publishing configuration and match the project version.
The workflow publishes Maven artifacts first, then checks that the core POM is
available on Central before uploading the Gradle plugin.

The registry selector defaults to both. Choose central to publish signed Maven
artifacts independently, or gradle to publish only the Portal plugin after the
matching core version is already available on Central. This supports completing
one account's setup before the other without republishing an immutable version.

If the Portal job fails after Central succeeds, rerun only failed jobs. Registry
versions are immutable: never rebuild different code under an existing version.
The plugin can remain pending review after a successful Portal upload.

The initial 0.3.1 Gradle submission is still pending approval. For the 0.4.0
preview, select central; upload the 0.4.0 Gradle update only after the initial
submission is approved. No tag or previously published artifact is replaced.

== Local verification without registry credentials

[source,shell]
----
mvn -Pcentral-publish -Dgpg.skip=true verify
./gradlew check validatePlugins :javadrift-core:publishToMavenLocal :javadrift-gradle-plugin:publishToMavenLocal
----

These commands verify packaging and install Gradle artifacts locally; they do
not validate credentials, signatures or publish to either external registry.
Even publishPlugins --validate-only requires Portal credentials.
