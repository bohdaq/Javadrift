= Diagnose project setup

The doctor command is available in the current source checkout. It is not in
the published 0.3.1 CLI; build the current source with mvn package first.

[source,shell]
----
java -jar javadrift-cli/target/javadrift.jar doctor --root /path/to/project
java -jar javadrift-cli/target/javadrift.jar doctor --root /path/to/project --format json
----

Doctor checks the running Java version, project root and YAML configuration,
selected documents and production Java/Kotlin source paths, automatically
discovered Maven/Gradle class directories, explicitly supplied class directories
and dependency jars/directories, and the configured baseline. It explains each
problem and the next action. It uses the same source selection, docs.include,
docs.exclude and automatic class-directory rules as check.

The default configuration is used when javadrift.yml is absent. A missing explicit
--config is an error. Relative --config paths use the working directory, matching
check; configured classes, classpath and baseline paths use the project root.
CLI --class-dir values are also relative to the project root unless absolute.
Repeat --class-dir to add multiple inputs. --classpath uses the platform path
separator: a colon on Linux/macOS and a semicolon on Windows. Empty classpath
entries are rejected to avoid accidentally relying on the working directory.

[source,shell]
----
java -jar javadrift-cli/target/javadrift.jar doctor --root /path/to/project \
  --class-dir target/classes --classpath "/path/to/dependency.jar"
----

Exit codes are 0 when setup checks pass, 1 for setup warnings and 2 for invalid
inputs. WARN covers no selected documents, no production sources or compiled
project inputs, and explicitly selected empty compiled outputs. Missing build
outputs are informational when source indexing is available: compile the project
for generated/inherited APIs or snippet checks. A runtime without javac is
accepted while JD008 is disabled; enabled JD008 requires a full JDK supporting
snippets.release. Doctor verifies that release with a small in-memory compiler
probe. A Java runtime older than 17 cannot launch the CLI to run doctor.

Doctor is offline and does not execute project code, parse sources/bytecode,
analyze documentation findings, compile project code or change project files.
It opens jars and counts class entries, but does not establish that every class
file can be indexed. The compiler probe disables annotation processing, uses
no project dependencies and discards generated bytecode in memory. Setup success
does not establish documentation correctness or dependency completeness; run
check afterward. Missing baselines are normal and mean findings are unsuppressed.

JSON output has schemaVersion, root, exitCode and diagnostics. Each diagnostic
has check, status (PASS, INFO, WARN or ERROR), message and optional advice.
Use --format json and redirect stdout when a CI setup report is useful.
